# Deliver Module Test Case Set — Organized by PRD Expected Behavior

> This document translates every requirement in [deliver-prd.md](./deliver-prd.md) into "expected behavior" test cases,
> serving as an **acceptance checklist + coverage tracker**. Each case is tagged with its automation status and where it lives.
> The executable version is in `tests/test_prd_acceptance.py` (organized by PRD section, exercising the
> full adapter→engine→submit→runner path end-to-end).

## Coverage Legend

| Marker | Meaning |

## Gap List (⚠️) and Recommendations

1. **Acceptance-level (run_delivery) coverage for B-3 / F-1~F-3** — registration/login/email verification are currently only covered at the component level (`test_auth`), not exercised through the full `run_delivery` path (because `ScriptedBrowserSession` maps a single URL to a single HTML page, which makes it hard to express "the gate page submits and jumps to the form," a multi-page navigation). Component-level coverage is already solid; adding acceptance-level coverage would need a stronger browser stub, and the payoff is medium-to-low.
