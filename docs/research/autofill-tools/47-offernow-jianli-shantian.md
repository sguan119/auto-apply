## 命名说明

经搜索确认，"OfferNow" 与"简历闪填"**是同一产品的英文名与中文名组合**，Chrome 应用商店的正式条目名即为"OfferNow简历闪填"（简历自动填写助手）。开发者本人在阮一峰《科技爱好者周刊》GitHub Issue（#8577）自荐以及牛客网技术分享帖中均以"OfferNow"指代同一款插件，故本文将两者作为同一调研对象处理，不再区分。

官网 offernow.cn 首页展示的是一个更大的产品矩阵，除"简历自动填写插件"外还包含"校招信息汇总"（一站式校招信息入口，按公司/城市/批次筛选、聚合内推与网申链接）功能，插件本身的产品/使用入口指向 cv.playoffer.cn / cv.offernow.cn。

## 核心实现方式（推测）

官方与开发者自述的工作流程大致为：用户在插件内维护一份结构化简历数据（JSON 形式）→ 打开招聘网站的网申表单页面 → 插件读取当前页面 DOM 结构 → 通过 AI 模型将表单字段与简历字段做语义映射 → 一次性批量将值写回页面表单控件 → 用户确认后自行提交。

开发者在牛客网技术分享帖中披露了相对具体的技术方案（这部分来自开发者自述，非第三方逆向，但比多数同类插件的公开信息更详细）：

- **DOM 剪枝（本地预处理）**：在把页面结构发给 AI 之前，先在浏览器本地剔除广告、导航栏等与表单无关的 DOM 节点，减少传给模型的上下文体积、降低误识别概率。
- **批量推断**：不是逐个字段调用模型，而是一次性提取整页表单结构，交给大模型返回"字段—值"的整体映射关系，再统一回填，减少延迟和 API 调用次数。
- **语义级字段识别**：官方举例称模型能把类似 `q1_v2` 这种无语义的字段 ID 正确识别为"期望薪资"，并能将简历里的日期格式（如"2023.09"）自动转换为目标网站要求的格式（如"2023-09-01"），说明其匹配不是简单的 name/id 精确匹配或关键词表，而是依赖大模型对页面上下文（label、周边文本、字段类型等）做整体理解。
- **数据本地化**：开发者自述简历数据"仅存储于浏览器 LocalStorage"，大模型只负责"逻辑处理"（即分析表单结构、返回映射关系），不留存用户数据，作为隐私卖点。

以上均为**开发者公开自述内容的转述**，本调研未获得插件源码或抓包验证，无法确认实际网络请求中简历原始内容是否会被发送至云端/大模型 API（若要做语义映射，理论上简历内容或至少其结构化字段需要传给模型端做匹配，这与"数据仅存储于本地"的隐私宣传之间的具体边界不完全清晰，值得读者自行注意）。

## 技术栈（推测）

- **浏览器插件框架**：开发者在 GitHub Issue 自述中提及前端技术栈为 **WXT + React 19 + TypeScript**（WXT 是新一代浏览器扩展开发框架，通常配合 Manifest V3）；后端为 **Next.js 15 + Prisma + MySQL**，用于账号、简历云同步等配套服务。
- **AI 模型**：两处公开自述存在版本差异——较早的 GitHub Issue 提到 AI 模块使用 **DeepSeek**；较新的牛客网技术分享帖（时间上晚于/或另一版本迭代）则称核心引擎升级为 **Gemini 3.0 Pro**，理由是其"语义理解能力和多模态能力"更强。推测产品在迭代过程中更换或增加了可选的大模型后端，具体以当前线上版本为准，本调研未能实测确认。
- **插件运行形态**：属于典型的 content script 表单填充类插件，在目标网页注入脚本读取/操作 DOM，并通过后台/云端服务调用大模型 API 做字段映射推断。
- **本地存储**：简历结构化数据据称存于浏览器 LocalStorage，具备"多设备同步"功能，说明存在云端账号体系用于跨设备同步简历数据。

## 支持平台/网站

官方及第三方转述口径一致，宣称支持 **BOSS直聘、智联招聘、猎聘** 等国内综合招聘平台，以及 **100+ 主流招聘网站**；牛客网技术分享帖进一步提及适配了主流第三方招聘系统/ATS（**Moka、北森、Taleo**）、**银行网申系统**（举例工商银行、建设银行，宣称通过率 90%+）以及互联网大厂官网招聘系统。另有资料称覆盖场景包括 LinkedIn 等海外职业社交平台。"前程无忧"未在检索到的资料中被明确点名提及，属于待确认项。

## 自动化程度（全自动 / 半自动，人工介入点）

综合多处描述（"减少重复输入，专注投递本身""填写完成后请仔细检查简历信息的准确性和完整性"），该工具定位为**半自动填表工具**：

- 插件负责"识别表单结构 + 批量回填字段值"这一步；
- 官方明确建议用户在提交前核对填写内容的准确性；
- 未见任何资料表明插件会代替用户点击"提交/投递"按钮，最终提交动作大概率仍由用户手动完成。

因此该工具应归类为"AI 辅助自动填表"而非端到端无人工介入的"全自动投递机器人"。

## 反爬虫/验证码/风控应对

未检索到任何官方或第三方资料专门讨论该插件针对验证码、平台风控/反爬虫机制的应对方案。基于产品形态可做如下推测：

- 插件运行在用户本人已登录的真实浏览器会话中，以 content script 方式操作页面 DOM（而非后台无头浏览器/远程自动化脚本发起请求），行为模式更接近"辅助用户手动操作"，理论上不易触发以 IP/设备指纹为主的传统反爬虫机制。
- 若目标招聘平台的前端对"非人工触发的表单填写/提交事件"有异常行为检测（例如要求滑块或图形验证码），该插件依赖"半自动、由人工完成最终提交"的流程设计，本质上是把最容易触发风控的"提交"动作交还给人工完成，从而规避风控问题——这很可能也是同类工具普遍停留在"半自动填表"阶段的共同原因之一。
- 以上均为**基于产品形态的合理推测**，未见任何公开资料明确说明验证码/风控应对细节。
